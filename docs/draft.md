# draft: 새 글 임시 저장

초안은 아직 게시하지 않은 새 글을 서버에 저장하고 다음에 불러와 이어 쓰는 기능이다. 게시글 수정에는 초안 저장을 제공하지 않는다.

## 사용자 흐름

1. 작성 전용 상단 헤더의 **저장 및 게시** 버튼으로 모달을 연다.
2. **초안 저장**을 누르면 제목·본문이 미완성이어도 저장한다. 선택한 썸네일·사진 목록·카테고리·추가한 태그·공개 설정도 보관한다. 아직 태그로 추가하지 않은 입력값은 서버 저장 대상이 아니다.
3. 작성 화면의 **내 초안**은 목록 모달을 연다. 제목과 마지막 저장 시각을 보고 선택하면 같은 작성 화면에서 이어 쓴다. 미저장 변경사항이 있으면 교체 전 확인한다.
4. 다시 초안 저장하면 같은 글을 갱신한다. 첫 저장 뒤 작성 URL은 `/write?draft=ID`가 된다. 새 초안이 필요하면 `/write`에서 새 작업을 시작한다.
5. **공개 게시 / 비공개 게시**에 성공하면 같은 글의 상태를 게시 완료로 바꾼다. 초안 목록에서는 빠지고 게시글 주소로 이동한다. 제목과 본문은 게시할 때만 필수다.
6. 이미 게시된 글은 **수정 → 수정 반영**만 제공한다. 초안 저장이나 다른 초안 불러오기 버튼은 없다.

내 초안 목록의 **삭제** 버튼은 확인 후 초안과 태그 관계를 같은 트랜잭션에서 삭제한다. 작성자 소유의 DRAFT와 마지막 저장 시각을 검사해, 타인 글·게시된 글·다른 탭에서 변경된 초안은 삭제하지 않는다. 삭제 실패 시 목록을 유지하고 오류와 목록 새로고침을 표시한다. 삭제 성공 후 해당 브라우저 복구본도 정리한다. 현재 작성 중인 초안을 삭제하면 편집 내용은 유지한 채 `/write`의 새 작업으로 전환하며, 다음 초안 저장은 새 ID로 생성한다. Storage 사진 파일은 삭제하지 않는다.

저장 실패 시 입력 내용과 모달을 유지한다. 사진 업로드가 진행 중이면 저장을 막는다.

## 데이터와 공개 범위

별도 `PostDraft` 모델이나 컬렉션을 만들지 않고 기존 `Post`를 사용한다.

| 필드                        | 의미                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------- |
| `status: DRAFT`             | 아직 게시하지 않은 글. 작성자 전용 초안 API로만 접근                                    |
| `status: PUBLISHED`         | 게시를 완료한 글                                                                        |
| `isPublished: true / false` | 게시된 글의 공개 / 비공개 범위. 초안 여부와 별개                                        |
| `updatedAt`                 | 마지막 저장 시각. 초안 목록 정렬과 동시 갱신 검사에 사용. 기존 글의 누락·null 값을 허용 |

새 초안은 임시 고유 slug로 저장하고, 게시 시 제목 기반 slug로 바꾼다. Post ID는 유지한다. `createdAt`도 실제 게시 시각으로 갱신해 일반 글 목록이 초안 생성 시각으로 정렬되지 않도록 한다. 같은 제목의 주소가 이미 있으면 게시를 거절하고 초안은 유지한다.

초안의 `img`에는 썸네일을 첫 항목으로 하고 업로드 사진을 중복 없이 보관한다. 게시할 때는 기존 게시글 동작과 동일하게 선택한 썸네일만 `img`에 남기며, 본문 사진 URL은 본문에 유지한다.

기존 MongoDB 글에는 `status` 필드가 없을 수 있다. 따라서 스키마의 status는 호환성을 위해 nullable이며, 일반 글 조회는 `PUBLISHED`, null, 필드 미존재를 기존 게시글로 취급한다. 기존 글의 `updatedAt`도 누락되거나 null일 수 있으므로 nullable로 정의한다. `db push`는 기존 문서의 날짜를 일괄 채우는 작업이 아니다. 새 글·초안 생성과 저장 시 날짜는 자동 기록된다. 날짜가 없는 초안은 응답에 null을 유지하고, 갱신 시 null과 필드 미존재를 함께 검사한다. 새로 쓰는 글에는 반드시 DRAFT 또는 PUBLISHED를 지정한다. 기존 비공개 글을 초안으로 바꾸지 않는다.

일반 글 목록·페이지 수·상세 화면·태그 조회와 집계에서 DRAFT를 제외한다. 관리자도 일반 글 목록에서 초안을 보지 않는다. 기존 글 수정 API를 이용해 초안을 수정하거나 게시할 수 없다.

## API와 안전한 저장

| 요청                            | 동작                                                  |
| ------------------------------- | ----------------------------------------------------- |
| `GET /api/drafts`               | 로그인한 사용자의 DRAFT 목록                          |
| `POST /api/drafts`              | 새 초안 저장 또는 ID와 updatedAt이 일치하는 초안 갱신 |
| `GET /api/drafts/[id]`          | 작성자의 DRAFT 한 개 조회                             |
| `POST /api/drafts/[id]/publish` | 같은 Post를 PUBLISHED로 전환                          |

초안 갱신과 게시 전환은 작성자·DRAFT 상태·마지막 저장 시각을 모두 검사한다. 다른 탭이 저장하거나 이미 게시한 글이면 409를 반환한다. 글과 태그 변경은 한 트랜잭션에서 처리하므로 실패 시 초안이 유지된다. 게시를 반복해도 새 Post가 추가되지 않는다.

브라우저의 `postRecovery`는 입력 유실 방지를 위해 유지한다. 새 작업·초안 ID·게시글 수정별로 구분하며, 서버 초안보다 최신인 브라우저 복구본만 추가 복원한다. 서버 저장 성공 후 해당 복구본을 정리한다. 브라우저 보관은 서버 초안 목록에 추가되지 않는다.

개발 환경에서는 전역에 보관한 Prisma Client를 재사용한다. Prisma 스키마를 변경하면 Client를 재생성하고 개발 서버를 재시작한다.

## 작성 전용 레이아웃

`/write`는 `(editor)` 라우트 그룹의 전용 레이아웃을 사용한다. 블로그 공용 내비게이션과 푸터를 적용하지 않으며, `WriteHeader`에 서비스 이름과 내 초안·저장 및 게시 버튼을 표시한다. 게시글 수정 시에는 수정 반영 버튼을 표시한다. 인증·Query·테마 공급자는 최상위 레이아웃을 계속 공유한다.

## 본문 글꼴

작성 화면의 본문 글꼴 드롭다운에서 명조체·고딕체·나눔고딕·나눔명조·고운바탕·고운돋움·시스템 기본을 선택한다. 마크다운 원문은 유지하고 Post의 nullable `fontFamily` 필드에 허용된 글꼴 식별자를 별도 저장한다. 선택값은 초안·자동 복구·게시·수정에 함께 반영된다. 기존 글과 복구본에 선택값이 없으면 현재 게시글의 기본인 명조체를 적용한다. 미리보기와 게시글은 같은 글꼴 설정을 사용하며, 마크다운 입력창과 코드 블록은 고정폭 글꼴을 유지한다. 임의의 CSS나 외부 글꼴 URL은 받지 않는다. 추가한 웹폰트는 preload를 끄고 본문이나 글꼴 목록에서 사용할 때 불러온다. 시스템 기본 글꼴은 기기에 따라 다르게 표시될 수 있다.

## 요청·응답 타입

`src/lib/zod/draft.ts`는 검증 스키마를, `src/types/api/draft.ts`는 해당 스키마에서 추론한 요청·응답 타입을 정의한다. 서비스·Query·컴포넌트는 타입 파일을 참조하고, API와 서비스는 런타임 검증에 스키마 파일을 사용한다. 서비스 함수에는 반환 타입을 명시하며 목록과 삭제 성공 응답도 스키마로 검증한다.

글꼴 허용값 검증은 `lib/zod/post.ts`, 화면용 타입은 `types/post.ts`, 기본값·글꼴 목록은 `lib/constants/post.ts`, 값 정규화는 `lib/utils/post.ts`에서 관리한다. 게시글·초안의 응답 변환 함수는 `lib/serializers/responses.ts`로 모은다.

## 클라이언트 Query

서버 상태는 `src/queries/draft.ts`에서 TanStack Query로 관리한다.

- `useDraftsQuery`: 내 초안 목록 조회와 재시도.
- `useDraftQuery`: 선택한 초안 상세 조회. 작성 화면은 최신 조회가 끝난 뒤 편집 초기값을 적용하며, 캐시 갱신으로 작성 중 내용을 덮어쓰지 않는다.
- `useSaveDraft`: 저장 성공 시 상세 캐시 갱신과 목록 무효화.
- `useDeleteDraft`: 삭제 성공 시 목록에서 제거하고 목록·상세 캐시 무효화. 현재 편집 화면의 갑작스러운 재조회를 막기 위해 상세는 즉시 재조회하지 않는다.
- `usePublishDraft`: 초안 목록에서 제거하고 게시글·태그 캐시도 갱신.

초안 Query 키는 계정별로 구분한다. 컴포넌트는 서비스를 직접 호출하지 않고 조회·mutation 훅의 로딩·오류·재시도 상태를 사용한다. 모달 표시, 삭제 확인, 편집 값과 브라우저 복구 상태는 컴포넌트에서 관리한다.

## DB 적용과 검증

```sh
npx prisma generate
npx prisma db push
```

새 구현은 Post의 status와 updatedAt 필드를 추가한다. Prisma Client 생성과 스키마 검증은 코드 작업에서 수행하고, 실제 DB 반영은 별도다. 개발 서버가 이전 생성 코드를 사용하면 재시작한다. 이전 실험의 PostDraft 데이터는 이 기능에서 조회하거나 이전하지 않는다.

API 테스트는 DB를 모의 처리한다. 권한, 같은 Post의 초안 갱신·게시 전환, 오래된 저장 시각 거절, 게시글 경로의 초안 차단을 검증한다. 작성 화면 테스트는 미완성 저장, 불러오기 모달, 같은 초안 이어 쓰기, 게시 전환과 수정 화면의 초안 기능 제외를 검증한다. 실제 로그인 브라우저와 MongoDB 트랜잭션 검증은 DB 적용 후 확인해야 한다.
