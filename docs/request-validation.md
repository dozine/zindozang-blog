# API 요청 본문 검증

게시글 생성·수정, 카테고리 생성, 태그 생성 API는 인증 검사 후 Zod로 JSON 본문을 검증한다. 검증에 실패하거나 JSON이 잘못됐으면 DB에 접근하기 전에 `{ message: string }` 형식의 400 응답을 반환한다.

스키마는 `src/lib/zod` 아래의 `post.ts`, `category.ts`, `tag.ts`에 도메인별로 나누어 두고, 공통 문자열 검증은 `common.ts`, 공통 JSON 파싱과 스키마 검증은 `parse.ts`, 요청 파싱과 400 오류 응답은 `request.ts`의 `parseApiRequest`에서 관리한다. 현재 필수 문자열의 공백 여부와 필드의 자료형을 검사한다. 기존 이미지의 문자열·문자열 배열·null, 선택적인 태그·공개 설정은 유지한다. 제목과 본문 등은 검증 과정에서 값을 변경하지 않는다.

Zod 스키마를 기준으로 요청 타입을 `z.infer`로 추론하고 `src/types/api`에서 제공한다. 현재 요청 스키마에는 입력과 출력을 달라지게 하는 변환이 없다. 프로젝트 전체에 `strict: true`를 적용하며, `npm run typecheck`로 전체 타입을 검사한다. 이 검사는 CI에서도 실행한다. [Zod 공식 문서](https://zod.dev/)도 strict 모드를 요구한다.

요청 검증은 위 네 요청의 본문과 카테고리 삭제의 `id` 쿼리 파라미터, 게시글 상세·수정·삭제의 `slug` 및 태그 상세·삭제의 `id` 경로 파라미터를 다룬다. 삭제 ID가 없거나 공백뿐이면 인증 검사 후 DB 조회 전에 400 응답을 반환한다. 클라이언트 서비스에서 사용하는 주요 API 응답도 Zod로 검증하며, 자세한 범위는 [API 응답 타입 기준](./api-response-types.md)을 참고한다. 게시글 목록 검색·페이지 등의 다른 쿼리 파라미터, 외부 서비스의 응답, 요청 크기 제한과 파일 업로드 자체의 검증은 포함하지 않는다. Zod 타입 선언과 TypeScript 검사는 데이터베이스 연결이나 OAuth를 검증하지 않는다.
