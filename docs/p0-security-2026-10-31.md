# P0 개선: 변경 API 권한과 비공개 글 보호

작업일: 2026-10-31

## 문제와 변경

현황 점검에서 카테고리·태그 변경 API에 서버 권한 검사가 없고, 태그 상세 조회로 비공개 글 본문이 반환될 수 있는 경로를 발견했다. 운영 공격 재현 없이 코드와 테스트로 수정했다.

`src/lib/services/requireAdmin.ts`에 공통 검사를 추가하고 다음 네 경로에 적용했다.

- `POST /api/categories`
- `DELETE /api/categories`
- `POST /api/tags`
- `DELETE /api/tags/[id]`

이메일이 있는 세션이 없으면 401, 관리자 이메일과 다르거나 `MYEMAIL`이 설정되지 않으면 403 JSON 응답을 반환한다. 요청 본문 처리와 데이터 조회·변경 전에 검사한다. 관리자 정상 작업과 미분류 카테고리 삭제 금지 정책은 유지한다.

태그 상세 API와 서버 데이터 함수 `getTagById`에는 연결된 게시글의 `isPublished: true` 조건을 추가했다. 태그 목록 API와 `getAllTags`의 개수도 공개 글만 집계한다. 이 읽기 경로는 관리자에게도 공개 데이터만 제공하며, 비공개 글 관리에는 기존 인증된 게시글 경로를 사용한다. 비공개 글만 가진 태그의 이름 자체를 숨기는 변경은 포함하지 않는다.

## 검증

`src/__test__/p0-security.test.ts`는 실제 Route Handler와 서버 데이터 함수를 호출하되 세션과 Prisma를 mock으로 대체한다. 운영 DB 연결과 데이터 변경은 발생하지 않는다.

- 네 변경 경로 각각의 비로그인·일반 사용자·관리자 설정 누락 거부: 12개.
- 관리자 생성·삭제와 미분류 보호: 5개.
- 태그 상세의 비공개 본문 제외, 공개 글 집계, 없는 태그 404: 3개.

쿼리 조건에 따라 공개·비공개 글을 돌려주는 fixture로 필터 누락 시 응답 검증이 실패하도록 구성했다. 실제 MongoDB의 쿼리 실행·트랜잭션을 검증하는 통합 테스트는 아니다.

프로젝트 디렉터리에서 Node 20.19.6으로 Jest `--ci --runInBand`를 실행해 20개 테스트가 통과했고, `tsc --noEmit --incremental false`도 통과했다. 새 패키지나 환경변수 값 변경은 없다.

변경한 TypeScript 파일의 ESLint 검사도 오류 없이 통과했다. 기존 console 및 미사용 인자 경고 12개는 남아 있다. 이번 작업에서 프로덕션 빌드와 실제 OAuth·DB 통합 검증은 실행하지 않았다.
