# 카테고리 없는 게시글로 이전

게시글의 `catSlug`가 `null`이면 카테고리가 없는 글이다. 전체 목록에는 표시되며 특정 카테고리 목록에는 표시되지 않는다. 요청에서 `catSlug`를 생략하면 수정 시 기존 값이 유지되고, `null`이면 분류가 해제된다.

기존 데이터 이전이 완료되어 애플리케이션은 더 이상 `uncategorized`를 특별 취급하지 않는다. 아래 스크립트는 이전 기록으로 보관한다. 해당 slug가 새 카테고리에 사용된 이후에는 이를 이전 대상으로 오인할 수 있으므로 재실행하지 않는다.

## 기존 MongoDB 데이터 이전

이 작업은 DB 데이터를 변경하므로 운영 데이터베이스의 백업과 대상 환경을 확인한다. 스크립트는 자동 배포나 빌드에서 실행되지 않는다. MongoDB 트랜잭션이 가능한 환경이 필요하다.

1. 이전 버전 앱과 새 버전 앱의 게시글·카테고리 쓰기를 중단한다. 이전 버전이 실행 중이면 기본 카테고리를 다시 만들거나 글을 다시 연결할 수 있다.
2. 새 코드의 Prisma 클라이언트를 `npx prisma generate`로 생성한다. MongoDB는 Prisma Migrate를 사용하지 않으며, 이 선택 관계 변경에 별도의 필드 DDL은 필요하지 않다.
3. **이전 대상 DB를 명시적으로 선택**한 환경에서 다음 명령으로 미리보기한다. 예시는 `.env.local`을 사용하므로 실제 대상 환경 파일이 맞는지 먼저 확인한다. 연결 문자열이나 환경 파일을 공유하지 않는다.

   ```sh
   node --env-file=.env.local scripts/migrate-uncategorized.cjs
   ```

4. 출력된 데이터베이스 이름, 기본 카테고리 제목과 글 수가 예상과 일치하는지 확인한다. `uncategorized`의 제목이 `미분류`가 아니면 중단하므로 실제 데이터의 의미를 먼저 확인해야 한다.
5. 확인이 끝나면 동일한 환경에서 적용한다.

   ```sh
   node --env-file=.env.local scripts/migrate-uncategorized.cjs --apply
   ```

   스크립트는 하나의 트랜잭션에서 `uncategorized` 글의 `catSlug`를 `null`로 바꾸고 기본 카테고리를 삭제한다. 여러 번 실행해도 이미 이전된 글은 다시 변경하지 않는다.
6. 미리보기 명령을 다시 실행해 대상 글이 0개이고 기본 카테고리가 없는지 확인한다. 새 버전을 배포한 뒤 글 생성·수정, 카테고리 삭제와 전체 목록을 확인하고 쓰기를 재개한다.

이전 후에는 이전 버전으로 단순 롤백하면 `catSlug: null`을 읽거나 글을 저장하는 과정에서 오류가 생길 수 있다. 롤백은 쓰기를 중단하고 백업을 복구하거나 데이터를 이전 형식으로 되돌린 다음 진행한다.
